# アプリについてくる付箋

中心目標は、作業中のアプリのそばでメモを編集し、付箋から関連する作業に戻れることです。

## ローカル試用 0.3.0-alpha.10

- ウィンドウの選択: 🔗を押して次に対象ウィンドウをクリックすると、その場に貼り付けます。Escで中止でき、30秒で選択を終了します。🔗の強調表示は実際の貼付中を示します。貼付中の🔗を押すと「外す？」になり、3秒以内にもう一度押すとデスクトップに戻ります。Escや3秒経過で取り消せて、Shift+クリックでは貼付先を変更できます。選択中は◎と点線枠にし、付け替えのキャンセルでは元の貼付を維持した旨を表示します。貼付先はツールチップと付箋の下部で確認できます。▾でタグと貼付先の表示を切り替えます。カーソル変更や常駐の入力記録は行いません。
- 文字サイズ: 本文上のCtrl＋スクロールで変更し、Ctrl＋0で14pxへ戻します。PC内のlocalStorageへ付箋パス単位で保存し、本文・Markdownやツールバーサイズは変更しません。
- 前面表示: 貼付中の付箋の左クリックと、ネイティブなウィンドウのアクティブ化の両方で、対象ウィンドウを付箋の後ろへ前面表示します。WebView内のクリックが届かないタイトルバーや最初のアクティブ化にも対応します。ウィンドウ選択中には元の貼付先を前へ出しません。通常の追従ループからは対象を前へ出しません。
- ウィンドウ追従: 人が選んだウィンドウへ付け、相対位置を保ちます。📌OFFでは貼付先のすぐ上の重なり順に従い、ほかのアプリが前面ならその下に隠れます。📌ONでは常に最前面に残り、貼付先が最小化されても最後の位置に残ります。OFF時の最小化は一緒に隠れます。この判断にはタブの情報を使いません。
- タブへのリンク: Chrome / VS Code拡張で接続した現在のタブを、付箋の▾から保存します。ウィンドウ追従とは独立して設定できます。
- 「↗ タブに戻る」をクリックすると、保存した既存タブを選択して対象アプリを前面に出します。タブ切替に応じて付箋を表示・非表示にはしません。
- タブが閉じていたらエラーを表示します。新しいタブを勝手に作らず、付箋本文も残します。
- リンクはセッション内の特定タブです。Chrome / VS Codeの再起動・拡張再読み込み後は接続とリンクを設定し直してください。同じ題名の別タブは別物です。
- VS Codeは通常のテキスト、テキスト比較、Notebook、Custom Editorタブが対象です。Terminal等の未対応タブでは明示的に案内します。

Markdownに本文・共有属性、PC側config.jsonにウィンドウ位置・貼付先・タブ参照を保存します。リンク機能はタブの本文やURL・ファイルURIを付箋アプリへ送信しません。VS Code拡張は既存タブへ戻るために、そのタブの入力URIをVS Code内部で使います。

## 実装の境界

Chromeは公式Tabs APIとNative Messaging、VS Codeは公式TabGroupsとshowTextDocument等を使います。既存実行ファイルの標準入出力ホストとPC内の小さい状態・要求・応答ファイルを使い、追加のネットワークサーバーやAgentの定期起動はありません。タブ状態はリンクの選択にだけ使い、付箋の表示ループからは参照しません。

0.3.0-alpha.6では、タブのリンクは作業へ戻るための参照です。タブによる付箋の自動表示切替はありません。

導入手順は[拡張のREADME](../extensions/README.md)を参照してください。
