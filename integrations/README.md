# Agent連携（任意導入）

Agentの返事待ちや画面操作を、Markdown Sticky Notesの付箋で知らせるための連携です。アプリ本体と同じMITライセンスで公開しています。アプリのインストーラーに自動監視は含まれません。

| 利用するAgent | 導入先 | 方式 |
|---|---|---|
| Codex Desktop | [Codexの導入手順](codex/README.md) | 明示登録したチャットのローカルイベント記録を末尾監視。非公開形式に依存する実験的な代替方式 |
| Claude Code／対応するDesktop環境 | [Claudeの導入手順](claude/README.md) | 公式Hookイベントからスクリプトを実行。Desktop固有イベント・transcript属性には版依存あり |

## 持ち運び方

このrepoをcloneするか、ソースZIPを展開し、必要な方のフォルダを丸ごと配置します。初回だけ、付箋アプリの導入、保存フォルダの登録、Agent側の設定が必要です。個人の設定・ログ・チャット一覧・実行状態・Hookの信頼済み情報は配布しません。既存のAgent設定を丸ごと上書きしないでください。

両方ともWindows向けで、Markdown Sticky Notes **v0.8.4**のCLIとNode.js **v24.22.1**で確認しています。npmパッケージのインストールは不要です。新しいバージョンや別PCでは、各手順の短い動作確認を行ってください。

SkillはAgentに読ませる手順、Hookはイベント時に実行する処理です。今回の連携には独自Skillは必要なく、Hook／監視スクリプトと設定例を収録しています。Pluginのワンクリックインポート形式にはまだなっていません。

## 保存と動作範囲

- Agent/modelの定期起動、新サービス、ポート待受、連携コードからの外部送信はありません。
- 通常の付箋フォルダにMarkdownを作り、アプリのCLIで表示・終了します。終了時はCreatedを保持し、`ended_at`と`archived: true`を記録します。
- 付箋には質問や操作目的の短い文と担当名、設定した場合はチャットリンクが残ります。共有画面・同期フォルダ・Git管理時はこの情報も対象になります。
- CodexとClaudeでは終了条件・確認済み範囲が異なります。特にClaudeのComputer Use／permissionは実イベント未確認で、permissionの並列終了には既知の制約があります。詳細はそれぞれのREADMEを確認してください。
- repoの更新だけで、コピー済みの連携や稼働中の監視は更新されません。停止してソースを更新し、設定・stateを保持して再開します。

## 開発時の確認

repo rootから `node integrations/test.cjs`。実際のAgentや付箋アプリを操作せず、合成イベントと一時フォルダで判定・状態遷移を確認します。
